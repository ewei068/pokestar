# Battle completion boundary

`processBattleCompletionRewards` now owns the existing trainer, Pokémon, quest, and mode callback effects that previously ran inside Discord's `getStartTurnSend`. The Discord renderer still invokes it for legacy in-memory battles, preserving current behavior.

The function also has a strict mode for durable completion. Strict mode propagates database failures, runs participant updates sequentially, and rejects callback-backed battles until their effects have durable mode handlers. The durable service now invokes it through `processDurableBattleCompletion` under a completion claim; tower and raid mode effects also run through the durable completion path. The claim prevents concurrent completion attempts but does not make the reward writes and completion marker atomic or individually idempotent. Interrupted or partially applied completion still requires reconciliation. Keep production durable starts disabled until that recovery boundary is verified; see the [production-readiness report](verification/production-readiness-2026-10-24.md).
