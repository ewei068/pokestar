# Local, agent-controllable tools for tile VFX

Researched 2026-10-12 from first-party documentation. Scope: author and play short, transparent tile effects from generated image textures. A CLI or script API can be driven directly by an agent; no MCP connector is needed for that workflow. **Blender Lab and Phaser Editor v5 do have official MCP integrations**, with the qualifications below. Neither is currently connected to this task, so availability here has not been tested. [Blender Lab MCP](https://www.blender.org/lab/mcp-server/), [Phaser Editor MCP](https://docs.phaser.io/phaser-editor/ai/mcp-server)

| Tool | Can an agent author without GUI control? | Output and role | Main constraint |
| --- | --- | --- | --- |
| **Aseprite** | **Yes.** Its batch CLI runs Lua scripts. The scripting API can create sprites, frames, cels, and images, load source PNGs, draw them into frame images, and save the result. [CLI](https://www.aseprite.org/docs/cli/), [Sprite API](https://www.aseprite.org/api/sprite), [Image API](https://www.aseprite.org/api/image) | CLI exports PNG sprite sheets and JSON frame data. Good for a pixel-art, offline asset pipeline. [CLI](https://www.aseprite.org/docs/cli/) | It is a frame editor, not a built-in particle simulation: the Lua script or artist must define how flames/embers move between frames. Aseprite is paid as a prebuilt app; its source can be compiled for personal use, and assets may be used commercially. [API](https://www.aseprite.org/api/), [FAQ](https://www.aseprite.org/faq) |
| **Blender** | **Yes.** It can run Python in background mode and render an animation from the CLI. Blender Lab also has an official experimental MCP server for Blender 5.1+ that exposes its Python API through an add-on and running server. [CLI](https://docs.blender.org/manual/nl/4.5/advanced/command_line/arguments.html), [Blender Lab MCP](https://www.blender.org/lab/mcp-server/) | Renders transparent PNG frames (configure transparent film and RGBA PNG), then an external step packs frames into a sheet. Good for volumetric/light-rich or painterly effects. [Render settings](https://docs.blender.org/UATEST/api/current/bpy.types.RenderSettings.html), [formats](https://docs.blender.org/UATEST/manual/en/4.5/files/media/image_formats.html) | Full 3D/scene tooling and longer renders add authoring overhead for small pixel tiles. The official MCP executes agent-generated code without guards and specifically recommends an isolated machine/VM; background Python is a more bounded route for this pilot. [Blender Lab MCP](https://www.blender.org/lab/mcp-server/) |
| **Phaser** | **Yes, in TypeScript/JavaScript.** Its particle emitter accepts a texture and configuration for position, velocity, acceleration, lifetime, tint, scale, emission zones, etc.; the effect can be authored directly in the repo. [Particles](https://docs.phaser.io/phaser/concepts/gameobjects/particles) | Renders live in the browser; no baked sprite sheet is required. Emitter settings can be changed and previewed through the VFX lab. [Particles](https://docs.phaser.io/phaser/concepts/gameobjects/particles) | It is a browser runtime/library, not a local asset authoring CLI. Integrating Phaser into the current React battle renderer is an architectural choice and could add a canvas layer just for effects. |
| **Phaser Editor v5** | **Yes, with its local MCP server.** It connects to a running editor and can inspect project assets, create/update scenes, and work with game objects. Its particle emitter has a visual Inspector. Phaser says agents can generate emitters from project assets, but its MCP reference cautions that many editor features remain unimplemented, so specific emitter-tool coverage should be trialed before purchase or migration. [MCP](https://docs.phaser.io/phaser-editor/ai/mcp-server), [particle properties](https://docs.phaser.io/phaser-editor/scene-editor/game-objects/particle-emitter-object-properties), [Phaser announcement](https://phaser.io/news/2026/04/phaser-editor-v5-release) | Produces Phaser scene/code assets for live browser playback, not a baked sheet by default. [Editor](https://phaser.io/editor) | Paid subscription; currently advertised at $12/month. Requires a running desktop editor. This is distinct from **Phaser Game Agent MCP**, whose cloud sandbox uses credits and is not a local-editor integration. [Editor pricing](https://phaser.io/editor), [Game Agent MCP](https://www.phaser.io/agent/mcp) |
| **PixiJS** | **Yes, in TypeScript/JavaScript.** Its `ParticleContainer` and `Particle` expose textured particles with position, scale, rotation, tint, and alpha. [ParticleContainer](https://pixijs.com/8.x/guides/components/scene-objects/particle-container) | Browser renderer with direct code control and no export step. [ParticleContainer](https://pixijs.com/8.x/guides/components/scene-objects/particle-container) | The documented `ParticleContainer` is a lightweight renderer; emission/lifetime orchestration must be coded or supplied by another library. The particle API is marked experimental, though stable, in the v8 docs. [ParticleContainer](https://pixijs.com/8.x/guides/components/scene-objects/particle-container) |
| **Pixelorama** | **Partly.** The desktop CLI can run headlessly and export existing projects as spritesheets or image sequences. [CLI](https://pixelorama.org/user_manual/cli/) | Free/open-source pixel-art editor with automated export. [Official repository](https://github.com/Orama-Interactive/Pixelorama), [CLI](https://pixelorama.org/user_manual/cli/) | Its documented CLI focuses on exporting a project; it does not document an Aseprite-like script interface for building frames or a particle effect headlessly. That makes it a weaker fit for autonomous authoring, though useful for a human editor. [CLI](https://pixelorama.org/user_manual/cli/) |

## Recommendation for Pokestar

Try **Aseprite/Lua first** for one Fire Special tile effect using the generated flame as one source layer, plus smaller ember and glow layers. Generate frames at a fixed tile resolution, export a transparent PNG sheet and JSON, then show the result in the existing VFX lab. This is the shortest fully scriptable route from the current pixel-style reference to a reviewable web asset. Its code should define motion, fade, and particle birth/death; the image supplies detail but cannot create motion on its own. [Aseprite CLI](https://www.aseprite.org/docs/cli/), [Image API](https://www.aseprite.org/api/image)

If the desired quality depends on continuously changing particle motion, **Phaser** is the next experiment: use the same textures, drive a small live emitter on each affected tile, and retain the existing battle event/renderer seam. This avoids producing a separate sheet for every variant, but puts a canvas runtime in the web client. [Phaser particles](https://docs.phaser.io/phaser/concepts/gameobjects/particles)

Reserve **Blender** for effects where lighting, smoke, or depth clearly beat the pixel-art workflow; use **Pixelorama** if the team prefers its manual editor. These rankings are recommendations for this project's tile-VFX goal, not claims that one tool is generally superior.
