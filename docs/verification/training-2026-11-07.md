## Implemented behavior

Collection inspection opens Train for that owned Pokémon. Back and Pokémon
navigation reveal the retained collection, including selection, search, sort,
labels and inspection state. The upgrade host owns Pokémon/return context;
Train owns location selection, transport, timer and totals. Its replaceable
child boundary admits later upgrade panels without a registry or inert tabs.

The browser waits one second before the first request and after every settled
response. Only one request can be pending. Stop cancels future operations but
counts an already-submitted operation once if its response is confirmed. Idle,
stopped and complete status is blank; active/pending status is “Training…”. The
footer reports only confirmed Pokémon EXP and signed EV deltas. Home and Berry
copy, shared identity/artwork, nine locations, six EV rows and the mobile select
match the approved study. The select reserves 38 px and insets its chevron 12 px.

The server derives each operation from current owned state and canonical bot
rules. Level 100 completes EXP eligibility; positive EV changes and Berry
reductions can continue. Reads and completed no-ops grant nothing. Successful
web ticks use the configured `/train` participation grant, currently 15 trainer
EXP / 50 money, replacing the generic web grant. Training has an independent
60-per-account/minute quota. Discord still performs one operation per command,
including its existing stored EXP at level 100.

## Real MongoDB and HTTP

Used a disposable standalone MongoDB on loopback port 27139 with dbpath
`/tmp/pokestar-training-mongo/db`, separate from any application database.
The normal Mongo handler, training/player services, canonical battle registry,
registered quest listeners and Express API ran against seeded owned Pokémon.
An injected local session-store entry supplied the authenticated actor; this
establishes session-authorized HTTP behavior, not a Discord OAuth login.

Observed:

- GET training returned nine server-derived locations and did not change the
  Pokémon, trainer, quest progress, EXP or money.
- A real accepted tick persisted its exact EXP/EV deltas and recalculated stats,
  updated EV quest progress and added exactly 15 trainer EXP / 50 money.
- Invalid body fields, missing session, foreign actor assertion, foreign origin
  and missing owned Pokémon were rejected through the actual HTTP middleware.
- At level 100, capped selected EVs produced `trained:false` with no write or
  grant. Berry reductions still persisted signed deltas and contributed their
  absolute sum to the existing EV quest. Zero EVs at level 100 produced a no-op.
- Deterministic concurrent edits to name, held item, party, backpack and money
  survived narrow Pokémon/quest writes. Concurrent EXP and nature edits caused
  real Mongo conditional-write conflicts. Simultaneous guarded training calls
  were accepted or conflicted without losing accepted Pokémon progression.
- Free Home remained usable; unowned facilities remained unavailable. Fresh
  trainer/Celebi context fed the next server projection.
- A fresh quota window accepted 60 no-ops, rejected request 61 with HTTP 429 and
  a positive Retry-After, and continued to permit a training GET. No grants were
  issued by those no-ops or the denial.

Harnesses and raw logs remain machine-local under `/tmp/pokestar-training-*`,
including `http.log`, `quota.log`, `backend-final.log`, `web-tests-repaired.log`
and `typecheck{,-baseline}.log`. No production data or credentials were used.

## Production-bundle browser acceptance

Served the final root and `/pokestar/` production bundles through a loopback
static server, proxying the real local API above. Chrome/Playwright observed:

- First request delayed by one second; successive requests were over one second
  apart. Stop produced no subsequent request. A delayed accepted response left
  a disabled Stopping control, then counted its confirmed gain exactly once.
- Level-100 Berry Farm reduced `[2,3,0,0,0,0]` to zero, displayed `−2 HP, −3 Attack`,
  stopped automatically and awarded one participation grant.
- Deliberately losing the response after the server accepted a tick paused the
  loop, refreshed with GET, left totals at zero and did not replay the mutation.
- A visibility-change event paused before submission; returning visible did not
  resume. This was an injected browser event, not physical background/suspend
  acceptance. Pokémon navigation disposed the timer. Browser Back/Forward
  returned to Train idle. Expiring the local session returned to sign-in after
  one rejected tick and produced no further submissions.
- At 1280, 900, 390 and 320 px there was no document horizontal overflow. The
  native phone select retained its 38 px text reserve and 12 px chevron inset.
  At 320×480, Train/Stop stayed visible above bottom navigation; content remained
  scrollable. The root/subpath selected-owned URL and Back preserved the base
  path, selected ID and unrelated query parameters. No page errors occurred.
- The review repair below passed in the production bundle: leave during a POST,
  finish pre-write collection reads, allow the write to complete, reopen Train;
  the server's new level appeared and no training automatically resumed.

## Review and disposition

A scoped simplification pass retained the shared canonical helper, narrow
operation boundary, feature-owned loop and small host seam. It introduced no
extra abstraction or test removal. One independent combined CE code review
covered rules, ownership/persistence, grants, HTTP, cache/scheduling, navigation,
source-level accessibility and plan completeness, using the repository's
single-review routing preference.

Completed receipt: `training-implementation-20261108`,
`/tmp/compound-engineering-501/ce-code-review/training-implementation-20261108/review.json`.
The reviewer found one P2 defect: departure-triggered pre-write GETs could make
old caches fresh before a submitted tick settled, causing stale-only refresh to
miss saved gains. Applied inline: after settlement for a closed feature, cancel
and invalidate affected reads only while its original account/epoch remains
active; discard the obsolete result and refetch current consumers. The added
regression failed before the repair (`1 !== 2` reads), passed afterward, and
passed the real browser reproduction. Full client tests/builds passed afterward.
No actionable findings remain. No second review pipeline was run.

## Limits

No deployment, flag change, issue closure, live Discord command, real OAuth flow,
physical-device or OS suspend/restart acceptance was performed. Discord adapter
compatibility is established by automated command/service characterization.
Existing legacy writers and cross-document Pokémon/quest/grant partial failures
remain within the approved reliability scope. Warnings pause the client and do
not replay a primary write; durable exactly-once receipts and transactions were
not added. The temporary acceptance processes were stopped after verification.
